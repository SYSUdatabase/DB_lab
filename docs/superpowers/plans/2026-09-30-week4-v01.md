## 3. 统一业务口径

1. **销售额与销量**：仅统计 `Orders.status = 'paid'`。pending、cancelled、refunded 均排除。销售额使用下单快照 `OrderDetails.subtotal`，不使用商品当前价格重算历史交易；销量分别标明套餐件数和 Token 数。
2. **订单粒度**：订单明细视图一行对应一个 `detail_id`。订单金额不能在一对多连接后再次直接求和；会员消费统计从 Orders 聚合，商品销售统计从 OrderDetails 聚合。
3. **余额**：按用户和 provider 管理；当前样例已支付购入 Token 减使用量等于余额。退款订单在该合成数据中未形成净充值。
4. **库存**：Inventory 与 UpstreamAccount 一对一，表示上游账号可用额度。`current_quota = total_quota - used_quota = SUM(InventoryLog.change_amount)`。
5. **补货**：有效账号指 `status = 'active'` 且未过期；低库存指 `current_quota < safety_threshold`。暂停、过期、耗尽账号单独显示状态，不能直接当作可用供给。
6. **固定时点**：库存状态视图使用样例快照时点 `2026-09-22T23:59:59`，输出 `as_of_time`，避免演示日期变化导致验收漂移。报告注明这是样例快照判断，不是实时监控。
7. **使用汇总**：daily、weekly、monthly 是同一批调用的三种聚合粒度。跨粒度相加会重复统计；每种粒度分别与原始日志核对。
8. **权限**：`dbo.Roles` 是应用层角色数据；SQL Server 的数据库角色是实际授权机制，二者分别说明。
9. **会员隔离**：数据库用户 `hub_user_1` 对应业务用户 1，`hub_user_2` 对应业务用户 2；个人视图按 `USER_NAME()` 过滤。不向会员开放全表 SELECT，也不使用可由调用者任意设置的 SESSION_CONTEXT 作为身份依据。
10. **阶段范围**：会员本周演示商品浏览、个人订单、余额和用量查询；店员演示待处理订单的取消/恢复待处理。真实注册、支付、退款、充值与补货事务、应用登录映射留在后续阶段。店员不能通过直接改状态执行支付或退款。

```sql
PRINT N'Q02 Paid product sales';
WITH s AS (
    SELECT d.product_id, SUM(CAST(d.quantity AS BIGINT)) AS units_sold,
           SUM(d.subtotal) AS revenue, SUM(d.total_tokens) AS tokens_sold
    FROM dbo.OrderDetails d JOIN dbo.Orders o ON o.order_id=d.order_id
    WHERE o.status='paid' GROUP BY d.product_id
)
SELECT p.product_id, p.name, p.model_provider,
       COALESCE(s.units_sold,0) AS units_sold,
       COALESCE(s.revenue,0) AS revenue, COALESCE(s.tokens_sold,0) AS tokens_sold
FROM dbo.Products p LEFT JOIN s ON s.product_id=p.product_id
ORDER BY revenue DESC, p.product_id;
```

- [ ] Q03 统计全部会员消费，LEFT JOIN 的 paid 条件写在 ON 中。40 行，其中 14 人金额为 0。

```sql
PRINT N'Q03 All member spending';
```

```powershell
    Write-Output "PASS v0.1 $DatabaseName"
}
finally {

}
```
