## 二、逐项技术复核

| 审查对象 | 对照 SQL Server / DDL 的证据 | 结论 |
|---|---|---|
| 14 实体与行粒度 | 逐个比较 `CREATE TABLE` 和 `data_dictionary.md` | 各业务表独立保存的理由、行粒度及主码与 DDL 一致 |
| 主码、候选码、复合候选码 | `sys.key_constraints` 输出 14 个 PK 和定义好的 UNIQUE | 候选码是**整个复合元组**，不是每个 UK 成员都单独唯一 |
| 17 条 FK | 核对父/子表、实际 FK 列、可空性、启用且可信状态 | ER 的 17 条关系与物理 v0.1 外码准确对应；无伪造的商品—库存直接 FK |
| 参与基数 | 结合 `FK`、`NOT NULL`、`UNIQUE` 判定 | 一库存恰好对应一上游账号，账号可有 0..1 个库存；订单可有 0..* 明细（业务期望 1..*） |
| 员工的多角色关系 | `RestockTask.created_by` 非空、`assigned_to` 可空；`InventoryLog.operator_id`、`ExceptionLog.handled_by` 可空 | ER 中各自保留独立线和角色名，不能合并为一条员工关系 |
| 多商品订单 | 当前 100 单、184 明细，68 单多明细，0 空订单 | 多商品已得到样例验证；**零空订单不等于 FK 强制** |
| 同单同商品 | `UQ_OrderDetails_order_product` + 样例重复行 0 | 数据库对同单同商品重复行设有限制，是否保留待业务决策 |
| 会员/散客 | `Orders.user_id NOT NULL` 且存在 FK；28 个有订单的用户 | 无账户散客未在当前结构实现，不能在报告中写为已支持 |
| 库存查询 | 上游账号缺库存 0，额度不一致 0；低库存样例 Gemini 2 个 | 当前数据通过，强制覆盖率及跨表配额等式仍非普通 FK 保证 |
| provider 匹配 | 样例无错配；调用日志的两个 FK 相互独立 | 现有 SQL 验证仅是查询时校验，不能冒充写入时约束 |
| 弱引用 | 异常关联 Orders、Inventory、TokenUsageLogs 各 4 行；3 行未关联；库存流水 3000 条 manual 引用、4 条 restock_task 引用、8 条无引用 | 不存在通用 FK；需明确每种引用类型的目标及生命周期 |
| 概念/物理区别 | `OrderDetails.detail_id` 独立 PK，所有 17 FK 不参与子表 PK | 是存在依赖/关联实体，但不应把现有主码标为严格弱实体复合标识 |
| 图与交付脚本 | 修正 `qa_week5.py` 根路径及旧 `report/week5` 链接，重新导出图例 | **已修复文件路径和脚本定位问题**；重新执行 QA 通过 |

## 三、v0.1 问题人工技术判定（第五周不做数据库迁移）

| 编号 | 技术判断 | 第五周处理 / 保留理由 |
|---|---|---|
| I01 | **缺少业务级保证**：每单至少一条明细 | 保留现有 0..* 物理基数；列为后续应用事务/提交校验，不能仅靠 FK |
| I02 | **需求歧义**：同一套餐同单多条独立明细 | 保留现有 `quantity`、`detail_id` 与复合 UNIQUE 的 v0.1 实际情况，待团队决定是否调整 |
| I03 | **功能边界**：完全匿名散客下单不可直接表达 | 明示“不支持”；先确定是否允许临时账户或匿名购买 |
| I04 | **可能的参与缺口**：账号允许 0 个库存 | ER 如实标注 0..1，是否改成业务强制 1..1 待确认 |
| I05 | **跨表约束缺口**：provider/有效期 | 保留产品、调用事件与上游账号的分离；记录需事务或其他实时检查 |
| I06 | **受控冗余需要管控**：订单汇总/配额快照 | 保留交易快照和审计流水，现阶段以 `verify.sql` 对账 |
| I07 | **职责模型有待确定**：自动任务 `created_by` | 不虚构系统员工；根据是否自动创建决定创建主体模型 |
| I08 | **弱引用风险**：异常/流水目标不是外码 | 文档明确逻辑关联，后续视实际引用类型规划关联表或校验 |
| I09 | **历史余额规则**：最终余额非负不等于每时刻非负 | 保留余额和调用日志；已有逐事件历史核验，应继续保留 |
| I10 | **合理保留**：`Roles` 应用角色与 SQL Server 数据库 ROLE 分离 | 两者不同层次，不应在 ER 中误画为同一表 |

**结论**：可以确认现有第五周实体、属性、标识、外码、物理基数的技术分析基本正确；这十项中部分为现有缺口、部分为未决业务口径，不能未经确认就擅自变更 v0.1。保留项 K01—K07 的理由见 `week5/v01_issues.md`。
